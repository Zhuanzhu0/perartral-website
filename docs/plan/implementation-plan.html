01What we are building

A single-page, scroll-driven landing site for Perartral. The layout follows the armory.in pattern: a preloader with a percentage count, a statement hero, short capability blocks, Featured News, a contact block and a heavy footer. Perartral's own brand, footage and interactions make it a different site, not a copy. The FPV canyon clips in the folder join the sections together as scroll-scrubbed transitions. Scrolling moves the drone through the terrain, which suits a company whose work is getting supplies through hard ground.

06Spatial browsing and touchable surfaces

Spatial browsing (xr-live)

  • An <xr-live> element with camera-controls, xr-mode="auto", xr-hands="gestures" and sound-feedback. Neutral tone mapping keeps the brand colours true.
  • A sandboxed text/three script builds a stylised terrain: a battalion hub, six forward posts, and routes by porter, pack animal, vehicle and helicopter arc, all in brand gold and brown.
  • Three spatial HTML cards (slot="spatial") hang in 3D space, one per HimSetu part. Each has data-xr-grab, so it can be grabbed and moved by hand in XR. The cards are added after the scene loads, which xr-live 1.3 requires.
  • Opens in a full-screen “Spatial view” layer from the HimSetu section. A desktop or phone visitor orbits with drag or pinch. On a headset, the same scene enters immersive mode.

Touchable surfaces (Three.js + THREE.Interactive)

  • HimSetu tablet: a 3D tablet with the real app layout (Receive, Issue, Count, Demand). Each key is a mesh registered with InteractionManager. Pressing a key depresses and lights it and adds a line to an on-screen log: “Saved offline · will sync.” The tablet tilts toward the pointer.
  • Hero rings: the three logo rings float in the hero. Hover or tap spins a ring and sends a gold pulse.
  • Footer rings: a larger metallic version. Drag to spin, and they settle back with spring physics.
  • Touch events are treated as pointer events. Render loops pause when off-screen, using IntersectionObserver.

07HimSetu map clip (HyperFrames)

  • Project: video/himsetu-map/, 1920×1080, 12 s, a seamless loop driven by a paused GSAP timeline registered on window.__timelines.
  • Story: contour terrain draws in, then the battalion hub appears. Six posts pop in with “offline” badges. Routes draw by transport mode with moving cargo dots, and a helicopter arc follows. A sync pulse runs when a link appears, the days-of-supply counters update, and the badges turn to “synced”.
  • Contours come from seeded, deterministic noise, never Math.random. All names and figures are labelled demo data, with no real locations, per the reference PDF.
  • Pipeline: hyperframes check, then snapshot to review frames, then render. ffmpeg then makes a web encode at 1280×720 H.264, faststart, around 2–4 MB.

08Performance, accessibility, responsiveness

  • Video: uses the provided _scrub encodes (every frame a keyframe) for exact seeking, with posters as the first paint. Clips load with preload="auto" only when within about one screen of view.
  • Mobile: same story, shorter pin distances. The custom cursor is off, and 3D uses a pixel ratio of at most 1.5. Touch drives every interactive surface.
  • Reduced motion: scroll-linked scenes still play, because they move only when the visitor scrolls. Smooth-scroll inertia, autoplay, grain and decorative loops are switched off.
  • Accessibility: semantic landmarks, a skip link, alt text, visible focus rings in gold, a keyboard-usable form and buttons, and AA contrast for text over video using gradient scrims.
  • Fallbacks: if WebGL fails, the tablet and rings fall back to static images. If xr-live cannot start, the spatial view shows a message and the static screenshots.
